# 通用多模态视频理解与自适应 Token 压缩工程规范

本文档详述面向长视频（10min ~ 2h+）的多模态思维导图生成中，如何平衡**全景深度理解**、**极低延迟（TTFT）**与**零冗余视觉呈现**的底层工程原理。

---

## 1. 传统无脑抽帧的瓶颈分析

在处理长视频时，若采取固定频率（如 1 FPS）等间隔全量抽帧：
* **Token 爆炸**：1 小时视频 = 3,600 帧 $\approx$ 90~100 万视觉 Tokens。
* **延迟黑洞（TTFT）**：模型在计算前缀注意力与全量特征时，首字输出等待时间（Time To First Token）高达 30~60 秒。
* **信息熵稀疏**：视频中 90% 以上的画面是静态背景垫片、主播面部特写或无实质变化的平移镜头，真正包含“架构图、流程闭环、状态机、对比表、数学坐标系”的高信息熵帧通常不超过 30 张。

---

## 2. 自适应双轨流水线架构（Adaptive Dual-Track Pipeline）

本工作流将视频解构为互相补充的两个正交维度：

```text
[ 输入视频媒体 (MP4/MKV) ]
          │
          ├───▶ 【轨道 1：时序语义流 (Semantic Stream)】 ───▶ 全文字幕/精准 ASR 文稿
          │      • 覆盖全片 90% 逻辑论点、事实论据与演进脉络
          │      • 文本体积小 (10~25k Tokens)，所有大语言模型秒级消化
          │
          └───▶ 【轨道 2：自适应事件视觉流 (Visual Stream)】 ───▶ 场景突变高熵帧 (15~30 张)
                 • 通过 ffmpeg select='gt(scene,0.35)' 过滤冗余平稳画面
                 • 精准捕获 PPT 翻页、架构拓扑展示、代码走带与数学模型
                 • 视觉 Token 压缩率达 95%+，实现毫秒级首字响应
```

## 3. 四级自适应降级阶梯与抽象输入协议（Degradation Ladder）

根据当前运行环境对媒体 Payload 的支持能力与算力边界，自适应匹配最佳模式：

| 梯级与协议 | 适用环境与特征 | 输入 Payload 组织方式 | 核心优势与抗幻觉收益 |
| :--- | :--- | :--- | :--- |
| **梯级 1：长媒体原生直传**<br>*(Native Media Stream)* | 宿主原生支持音视频文件句柄与云端持久化缓存 | 传递媒体文件 URI / 句柄与结构化指令；$\gt 60\text{min}$ 自动按 45min 切片 | 视听一体化理解，超长视频自动分段防中间遗忘 |
| **梯级 2：时序图文混排自适应流**<br>*(Interleaved Multimodal - 默认推荐)* | 宿主支持多图查看与长文本混合输入 (Claude / GPT-4o / Gemini Flash) | 带秒级时间戳文稿 + `keyframes_manifest.json` 候选帧清单交错编排 | 兼容性 100%，首字响应提升 5~10 倍；锁死候选帧，**阻断盲截时间戳幻觉** |
| **梯级 3：纯文本语义流极速通道**<br>*(Pure-Text Fast-Track)* | 纯文本模型 (DeepSeek-R1 / Qwen-Coder / 本地开源模型)，或纯理论讲座 | 挂载 `--skip-download`，仅消费清洗文稿，跳过视频与抽帧 | **10~15 秒极速收敛，100% 免疫坐标与画面幻觉**，带宽消耗降为几百 KB |
| **梯级 4：无字幕/轻音频 ASR 兜底通道**<br>*(Audio-ASR Fallback)* | 平台无外挂 CC/AI 字幕的音视频源 | 抽取轻量纯音频轨 (`_audio.m4a`)，调用本地 Whisper 或云端 ASR | 快速自愈生成秒级时间戳文稿，无缝接回上述梯级 |

## 4. 视觉信息熵判定与图文表格降级铁律（Text/Table Superiority Protocol）

严禁为了“配图”而强行插入低信息熵截图。必须严格执行以下准入与降维筛选：

### 4.1 绝对降级准则（Mandatory Downgrade Rules）
* **大字提纲与文字列表幻灯片**：画面仅包含若干标题、文本项目符号、大字卡片。
  $\Longrightarrow$ **坚决不配图！** 直接转化为 3 级 Markdown 树状节点或 Unicode 流程链（如 `客户端 → DNS → 服务器`），信息密度高且支持全文搜索。
* **二维对比与参数罗列**：画面为讲师手写或 PPT 列出的 2~3 个方案对比或端口参数清单。
  $\Longrightarrow$ **坚决不配图！** 直接降维为 2×3 或 3×3 Markdown 微表格，阅读体验完胜图片。
* **零配图合规性声明**：对于纯理论讲座、大字课件类视频，**产出 100% 纯文本+微表格的零配图导图是完全合规且鼓励的最高质量形态**。

### 4.2 严格准入准则（Strict Image Admission Criteria）
仅当画面具备以下**纯文字与表格无法优雅表达的非树形高维信息**时，才允许嵌入图片：
* 包含多层回路、分叉与汇聚的复杂系统架构拓扑；
* 密集走带与专业软件 GUI（如 64 轨 DAW、Wireshark 抓包瀑布流、芯片引脚拓扑）；
* 连续函数坐标系、状态跃迁立体模型。

## 5. 场景自适应五大视觉呈现与批注模式矩阵（Adaptive Visual Matrix）

针对入选的高信息熵图表，严禁机械式地给每张图套粗红框（避免引发信息权重偏袒与认知失真），必须根据知识拓扑自适应匹配最佳模式：

| 模式编号 | 视觉呈现模式 | 适用场景与典型图像 | 批注与渲染规范 | 核心认知理由 |
| :--- | :--- | :--- | :--- | :--- |
| **模式 0** | **零标注客观纯景**<br>*(Pure Panorama)* | 系统架构全景、状态机全貌、生化回路闭环、官方宏观大表 | 自动智能清除黑边与播放器边框，微调对比度与锐度，**绝对不画任何红框或角标** | **平权客观**：全景图本身各组件具有同等重要性，强行画框会破坏平衡，造成信息偏袒。 |
| **模式 1** | **微观局部焦点引导**<br>*(Micro-Focus Callout)* | 极其密集的复杂工程界面、大拓扑图中的局部微观组件分析 | 极细双层对比框（外暗红+内鲜红 `#FF2D55` 2px），可选聚光灯外围微暗角（`--spotlight`），智能避让顶部标签 | **视线减负**：读者无法在 1 秒内从上百个旋钮或复杂代码堆中找到讲师指代的核心点，需瞬间视觉锚定。 |
| **模式 2** | **双向平权对比批注**<br>*(Symmetric Dual-Box)* | Client vs Server 双端交互、新旧协议握手差异、A/B 方案对峙 | 对称双色框（冷青蓝 `#00C7BE` vs 暖珊瑚红 `#FF3B30`），双端对齐标签（`--boxes "b1;b2" --labels "端A;端B"`） | **对等平权**：确保对比双方具有等同的视觉权重，避免单向偏向。 |
| **模式 3** | **时序胶卷水平拼接**<br>*(Temporal Filmstrip)* | 动态交互拖拽演示、算法状态演变、Before/After 前后对比 | 提取 2~3 个时间戳（`--timestamps`），裁黑边后等高水平拼接，打上 `[Step 1]`、`[Step 2]` 胶卷角标 | **动态降维**：单张静态图无法表达时序过程，多图零散插入又占用过多垂直高度，胶卷拼接提供紧凑连贯的阅读体验。 |
| **模式 4** | **图文表格降级回退**<br>*(Text/Table Fallback)* | 演示用大字 PPT、简单三四步线性流程、文字列表 | **零图片**，直接采用 Markdown 原子化节点、Unicode 链路（`→`）与微表格 | **高效纯净**：以文字与表格的极高密度取代低效截图。 |

## 6. 顶级工业级知识批注图元矩阵（对标 CleanShot X / Shottr 标准）

在基础呈现模式之上，为满足多步骤因果分析、微小细节放大与隐私保护等复杂诉求，引擎深度集成以下 5 种可组合的高阶图元：

| 高级图元 | 参数调用指令 | 视觉渲染规范 | 认知减负原理 |
| :--- | :--- | :--- | :--- |
| **步骤序号球**<br>*(Step Pins)* | `--steps "x,y:标签;..."` | 立体高饱和度圆形内胆（`①` `②` `③`），外圈柔和投影与双层描边，附带自适应展开的圆角胶囊药丸文本 | **因果时序降维**：静态拓扑无法直接看出执行流，打上步骤球后读者能以 0 思考成本顺着数字阅读整个调用链。 |
| **画中画放大镜**<br>*(Loupe Magnifier)* | `--zoom "cx,cy,r"`<br>`[--zoom-scale 2.5]` | Lanczos 算法抗锯齿放大，悬浮于空旷对角角标，带外发光投影与准星雷达引导线 | **微观细节保真**：对密集 IDE 代码或芯片引脚进行局部无损放大，既保留宏观背景又不失微观清晰度。 |
| **真实光学荧光笔**<br>*(Optical Highlighter)* | `--highlight "box;..."`<br>`[--highlight-color yellow]` | 正片叠底光学半透明叠加（Alpha ~35%），带微圆角，文字笔画清晰透射 | **文本权重锚定**：模拟纸质划重点质感，不产生生硬遮盖，瞬间突出关键代码行或核心配置。 |
| **双层对比定向箭头**<br>*(Directional Arrow)* | `--arrow "p1->p2:标签;..."` | 起点带实心定位锚点圆，箭身与锐利三角形头部采用外暗内亮双层描边，中轴悬浮文字徽章 | **跨组件流向明晰**：无论是亮底还是暗底，双层描边保证箭头跨越复杂组件时永不发生“断流”。 |
| **隐私凭据脱敏**<br>*(Privacy Redaction)* | `--blur "box;..."`<br>`--pixelate "box;..."` | 局部高斯平滑滤波或整齐网格马赛克，边缘柔和羽化过渡 | **工程合规安全**：自动消除讲师原片中的私有 IP、内部域名、生产环境 Token 与密码，保障交付安全。 |
